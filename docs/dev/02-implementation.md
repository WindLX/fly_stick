# 实现细节

设备事件、池状态与设备生命周期都由 Rust 管理。`PyJoystick` 暴露每次读取的事件差分；`PyDevicePool` 用单个 Tokio 监视任务将差分合并为完整快照，并向 Python 暴露两种读取入口。

## 读取模型

`Joystick::get_events()` 以非阻塞方式读取 evdev 队列。轴和帽的 `JoystickState` 只包含当前读取批次命中的 code；按键差分保留当前读取批次的最终状态，另附有序按下/释放序列，使同批内的快速按下与释放仍能生成 Trigger 脉冲。evdev 按键重复值 `2` 被忽略，不会被映射为释放。

设备池按 `DeviceDescription::build_state()` 建立完整零快照。监视任务把事件合并到快照：轴和帽保存最新值，按钮保存真实按住状态并计数按下边沿。快照版本在每次已接受的状态变化时递增，所以短按后立即释放也能唤醒 `fetch()`，即使最终快照与之前相同。

Hold 直接返回物理按钮状态。Trigger 对每个读取入口保留独立的按下计数游标；观察时把新计数折叠成一个 `1`，多次未观察的按下合并成一个脉冲。方向帽始终使用快照状态，不参与 Trigger 计数。

## 去抖

去抖时间按逻辑设备与按钮 code 记录，只检查按下边沿。释放不经过去抖，轴与方向帽不经过去抖。这样快速释放不会被丢弃，也不会把快门或帽方向留在错误状态。按钮按下在去抖窗口内被忽略；按住状态下的重复 down 值不增加 Trigger 计数。

## 生命周期与错误

`reset()`、`stop()` 通过生命周期锁串行化；读取路径不获取该锁。重置流程先停止旧任务并等待它退出，再重新枚举、按名称及可选路径匹配，随后预打开所有设备。只有所有打开都成功才更新状态并启动监视。成功返回逻辑设备名到 `(DeviceDescription, JoystickInfo)` 的映射，空配置返回空映射；任何匹配、配置或打开失败都会让池保持停止并释放已打开句柄。

一个监视任务独占所有 `Joystick` 文件句柄。`stop()` 发送停止信号并等待任务 join 完成，因此返回时所有 fd 已释放。读取故障会先丢弃所有 `Joystick`，再写入池错误并通知读取者；下一次读取得到 `OSError`，之后池保持停止，必须显式 `reset()` 恢复。未运行时读取与并行第二个 `fetch()` 抛 `RuntimeError`，设备不匹配为 `LookupError`，配置歧义或重复为 `ValueError`，超时为 `TimeoutError`。

## 读取并发

`fetch()` 使用原子占用标志保证一个等待者；等待期间不持有生命周期锁或数据锁。取消 future 会通过 RAII 清除占用标志；`stop()` 改变运行状态并通知等待者。第二个同时等待的 `fetch()` 立即拒绝。

`fetch()` 和 `fetch_nowait()` 分别维护版本与 Trigger 游标，交替读取不会消费另一入口的进度。不同 Python 消费者若都想用阻塞 `fetch()`，必须在调用侧仲裁；池只允许其中一个等待。事件在观察间会合并到快照，Trigger 对同一按钮的多次未观察按下也会合并为一个脉冲。

## 验证边界

设备匹配、快照 reducer、按下/释放、短按脉冲、去抖、取消、停止、预打开失败清理和读取故障由 mock 事件源覆盖，不需要真实手柄。`Joystick::new()` 与内核 evdev 节点的权限和具体轴码仍需在 Linux 设备上检查；单元测试不宣称验证了硬件时序。
